# Admin UX review

Goal: a non-technical studio owner can do everyday jobs without help. Principles applied (Apple HIG-style): purpose and simplicity (common path first, advanced one level deeper), agency and forgiveness (Undo instead of confirm; confirm only for irreversible loss and say what is lost), familiarity and consistency (same thing, same place), flexibility (keyboard, touch, RTL), craft, wayfinding, four kinds of feedback (status, completion, warning, error), plain direct labels, press feedback on pointer-down, 44 px targets, reduced-motion / transparency / contrast honoured.

## Findings by theme

- **Jargon.** "Page copy", "namespace", "key", "Settings keys", "Hero slides", "Series" (for the voices), "Account". Replaced with: Pages & text, Photos & media, File library, People, Voices, Site settings, My account. Group headers in the text editor are people-names ("Opening section", "Team") with a peek of the actual text when collapsed; the raw key is only a tooltip and a small line in search results.
- **Dead end.** Sidebar "Hero slides" and its dashboard card edit a table the public site no longer reads. Retired from navigation; `#hero` redirects to `#images`; the editor and the data are untouched.
- **Inconsistent patterns.** Three save styles (per-card Save, Save-order bar, modal submit), text-link vs filled buttons, `window.confirm` in five places. Now: explicit-save forms use one sticky bar (Unsaved changes + Discard + Save, Ctrl+S), instant things (show/hide, reorder, remove, reset text, discard drafts, delete message) apply at once with Undo, and the only confirmation is a sheet for deleting a project/category/person (irreversible, names the consequence) and for leaving with unsaved work.
- **Unclear save state.** Added: "Unsaved" badges, dirty dots in the nav and bottom tab bar, the bar's "All changes saved" flash, inline "Saving…", guard on sign-out and on closing a dialog (names what is lost), browser leave-warning kept.
- **Missing feedback.** Skeleton shimmer while the list loads; toasts for completion; errors say what happened and the next step ("Check your connection and try again"); never raw server strings.
- **Wayfinding.** Every section: title, one sentence, "View on site", primary action in the same top-end spot; skip link; focus lands on the new panel; breadcrumb-like page card in Pages & text.
- **Mobile.** Sidebar becomes a bottom tab bar (Home, Pages, Projects, Messages, More); "More" is a sheet with every section and a sentence each. Save bar and toasts sit above the tab bar.

## Decisions and trade-offs

- Unsaved edits survive switching sections (panels stay mounted), so a navigation guard is only needed for leaving the admin (sign-out, close tab). Section switching shows a dot instead of a dialog.
- Motion: CSS transitions with a spring-shaped `linear()` curve (~0.3 s, transform and opacity only, no overshoot) instead of adding Motion to every control: they are interruptible and cheaper. Press feedback is instant (`:active`, 40 ms). The palette and keyboard actions are not animated.
- Materials only where they separate layers: sticky save bar, bottom tab bar, palette, editor footer. Falls back to solid under `prefers-reduced-transparency` / `prefers-contrast: more`.
- Fields are boxed (they were hairline underlines) so they read as editable; filled accent buttons are the primary action everywhere (editors' `lbf-cta` is restyled in the admin scope, so the other editors match without edits).
